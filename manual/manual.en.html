JavaVisualizer User Manual

日本語

JavaVisualizer is a web app for learning how a Java program runs step by step, by watching it through a variety of visualizations. It uses the same screen and views as JSVisualizer (JavaScript) and PyVisualizer (Python).

  • Just open it in an up-to-date desktop browser (Chrome, Edge, Firefox, Safari, etc.). No installation or sign-in is needed, and you do not need to install Java (the JDK).
  • Programs run on a Java interpreter built into JavaVisualizer. It is separate from Java itself; see “2. Preparing code” for the supported part of Java. Its results have been checked against real Java on many programs.
  • As in real Java, the program is compiled before it runs, and mistakes such as type errors are reported first (see When an error occurs).
  • All code runs inside your browser. Your code and your operations are never sent to a server.

Writing your own code

In edit mode you can freely change the code on the left, or paste code written elsewhere. When you are done, press “▶ Run”.

  • Write the program in one file. It runs public static void main(String[] args) of the first class (the same as java Main.java). You can write other classes in the same file.
  • Use System.out.println(), System.out.print() and System.out.printf() to check results; output appears in the console. Values read by Scanner are written in advance in the “Input” box (see Using Scanner). Reading and writing files is not available.
  • Edited code is not saved. Reloading the page restores the original, so keep a copy of any code you want to keep.

The supported part of Java is as follows.

Some displays differ from real Java.

  • NullPointerException messages name what was null using variable names (because "n.next" is null), as when running in an IDE
  • The number in Point@1b6d3586 (the hash code) when printing an object differs from real Java
  • Math.random() returns the same sequence every run (the values differ from real Java)

Method calls stop with a StackOverflowError when nested deeper than about 200 levels (real Java allows thousands or more).

Using Scanner

JavaVisualizer runs the whole program first and then lets you step through it, so you cannot type input while it is running. Write the values that Scanner reads in the “Input” box below the source before pressing “▶ Run”.

  • Write import java.util.Scanner; and create it with Scanner sc = new Scanner(System.in);
  • sc.nextInt(), sc.nextDouble() and sc.next() read the next value separated by spaces or new lines. sc.nextLine() reads the rest of the line (a nextLine() right after nextInt() returns the rest of that line — an empty string — as in real Java)
  • If there are not enough values you get a NoSuchElementException; if a value cannot be read as a number, an InputMismatchException

Opening a shared link

If you open JavaVisualizer from a link that points to specific code (for example, one handed out in a class or in course materials), the app starts with that code loaded. The sample selector then lists only the linked code instead of the built-in samples (and cannot be changed when there is only one piece of code).

3. Edit mode and Run mode

ButtonDescription
✏ EditSwitches to Edit mode, where you can edit the code freely. The sample selector is available only in this mode
▶ RunRuns the code and switches to Run mode. The program runs to completion at once and every step is recorded. You can then use the stepping buttons to move forward and backward to any point and look at the state at that moment

After editing the code, press “Run” again to re-run it with your changes.

When an error occurs

If the code has a mistake, an error message appears below the code. As in real Java, some mistakes are found before the program runs (syntax and compile errors) and others while it runs (runtime errors).

LabelMeaning
Syntax ErrorThe code cannot run because of how it is written (a missing ;, a missing bracket, etc.). The message shows the line of the mistake
Compile ErrorThe code is written correctly, but types do not match (int x = 3.5;), a variable is not declared or is used before it has a value, a return is missing, etc. Mistakes are found before running, even in code that would not run. The messages are the same as the Java compiler (javac)
Runtime ErrorAn exception occurred while the program was running and nothing caught it (an array index out of range, an integer divided by zero, a field of null, etc.). The message is the same as real Java (Exception in thread "main" java.lang.ArithmeticException: / by zero). You can still step through everything up to just before the error

If execution exceeds 50,000 steps, it is stopped and reported as a runtime error, since the program may be stuck (for example, in a loop that never ends). You can step through everything up to the point where it stopped.

4. Stepping

In Run mode, the buttons at the top let you move execution forward or backward one step at a time. There are four kinds of buttons, each moving by a different amount, and each has a “back” and a “forward” version.

Four granularities

ButtonsGranularityOne press moves
◀ Expr / ▶ ExprFinestOne expression evaluation at a time. For a[j] > a[j + 1] it stops at the value of a[j], the value of a[j + 1], and then the result of the comparison. Use it to see the order in which an expression is computed
◁ Human / ▷ HumanMedium (start here)One meaningful change — the kind of thing a person would write down when tracing on paper: an assignment, an if condition, a loop condition, the loop variable of an enhanced for loop taking its next value, a method call, an exception being caught, and so on
◀◀ Stmt / ▶▶ StmtCoarseOne statement at a time, skipping the detailed computation inside it
⏪ Func / ⏩ FuncCoarsestStraight to the next point where a method is entered or returns. Use it to follow the overall flow of recursive calls

If in doubt, step with “▷ Human”. Use “▶ Expr” only where you want more detail, and “▶▶ Stmt” or “⏩ Func” to fast-forward through loops and method calls.

6. Visualization views

The right side of the screen shows the program’s behavior in many different forms. Use the tabs at the top to switch among 12 views. Which view is easiest to understand depends on what you want to know, so try several and find the ones that work for you.

  • Some views cannot be used with some code; their tabs are grayed out (for example, “Subst” is unavailable for code that calls no methods other than main).
  • The tab you used last is selected again the next time you open the app.

How the views are organized

The 12 views can be organized along two dimensions: what you look at and how time is shown.

What you look at falls into three groups:

  • State: the values the program holds at a given moment (variable values, the methods being called, the contents of memory)
  • Behavior: how the program proceeds over time (the order in which expressions are computed, the order and number of times statements run, the order of method calls). Expressions, statements, and methods correspond to the Expr, Stmt, and Func granularities of stepping
  • Arrays and objects: data that holds several values together

How time is shown comes in two kinds:

  • Views of one moment (animation): show only the current moment and change each time you step
  • Views of the whole run (timeline): use one direction of the screen for the flow of time and show the course of execution all at once, with the current moment highlighted

Comparing the same thing in a “one moment” view and a “whole run” view deepens understanding. For example, to see how a variable changes inside a loop, check its current value in “Variable” while lining up the values of each iteration in “Exec Trace”.

Views of state

TabTimeContents
VariableOne momentA table of code lines (rows) × variables (columns). Each row shows the variable values when that line last ran; values that changed since the previous step are in bold orange. You can show/hide columns and reorder them by dragging
Exec TraceWhole runLists the steps where assignments, condition tests, and the like happened, in execution order from top to bottom, with the variable values at each step and whether each condition was true or false. For code that uses arrays, each step also shows a small diagram of the array and where variables such as i and j point, so you can compare iterations
Call StackOne momentShows all current variable values, grouped by each method call in progress, together with their types (int x = 3). static fields appear under “static”. Inside methods you can see that every call has its own variables. When the program has finished, main has finished too, so nothing is shown
LifetimeWhole runWith time running horizontally and call depth vertically, shows each method call as a band from when it started to when it ended. Each band is labeled with the method name, its arguments, and that call’s variable values, showing how long arguments and local variables exist. The vertical dashed line marks the current moment
MemoryOne momentDraws variables (the stack) and the actual arrays, objects and strings (String) (the heap) separately, with arrows showing what each variable refers to. Two variables referring to the same array, or two strings for which == is true, point to the same box

Views of behavior

TabTimeContents
ExprOne momentShows how the one-line expression being computed turns into its final value as its parts are replaced by values. Orange marks the part just replaced; bold blue marks the part computed next. Parts skipped by && or || stay as they are
SubstWhole runShows, from top to bottom, how recursive calls expand as each call is replaced by the expression it returns: fib(5) → fib(4) + fib(3) → …
Control FlowOne momentFor each method, a flowchart that splits each if into true and false columns, draws a switch as a branch for each case, and indents loop bodies, with the current line emphasized. Each row's “×N” is how many times it ran over the whole run, and rows that never ran are grayed out. Deeply nested flowcharts scroll horizontally
HeatmapWhole runShows how many times each line ran, as color intensity and “count so far / total”. The dots on the right show when each line ran, so lines repeated in loops stand out at a glance
Call TreeOne momentShows method calls as a tree. Each node shows arguments and the return value; dashed gray means not yet called, thick blue means running, and green means finished. The cost at the bottom left is the number of calls in that node’s subtree (including itself) — handy for checking how many times a recursive method is called

Views of arrays and objects

TabTimeContents
ArraysOne momentShows array elements as cells colored by value. For variables used as indexes, such as i and j, the element they point to is marked below the cells. Choose which arrays to show with the buttons at the top. To see an array over the whole run, use “Exec Trace”
ObjectsOne momentShows references between arrays and objects as a graph — well suited to linked lists and trees

The tab order differs from the grouping above (from the left: Call Stack, Variable, Exec Trace, Subst, Expr, Arrays, Heatmap, Call Tree, Lifetime, Control Flow, Memory, Objects). This organization follows Table 1 of Tanaka & Ueda, “Proposal for Program Execution Environment that Visualizes Program Behavior Using Multiple Views” (IS-26-049).

8. Troubleshooting

ProblemWhat to do
The stepping buttons are not shownYou are in Edit mode. Press “▶ Run”
The sample selector is not shownYou are in Run mode. Press “✏ Edit”
NoSuchElementException saying there is no more inputScanner has no more values to read. Write the values in the “Input” box below the source (see Using Scanner)
A message says the first class has no public static void main(String[] args)The program runs from the first class. Put the class with the main method at the top of the file (after any import lines)
A message says something is not supported yetThat part of Java is not supported by JavaVisualizer yet (see the table in 2. Preparing code). Rewrite it in a supported way (for example, use an array instead of ArrayList)
An error is reported in code that does not runAs in real Java, compile errors are found by checking the whole program before it runs. Fix the line with the error
The sample selector cannot be changedYou opened a link to a single piece of code. To use the built-in samples, open the JavaVisualizer top page again
A Runtime Error says execution stopped because it exceeded the maximum of 50,000 stepsA loop or recursion may never end. Step through up to where it stopped and check the exit condition. If the program simply does a lot of work, use smaller data
Keyboard shortcuts do not workIf the cursor is in an input area such as the code editor, keys go there. In Run mode, click somewhere else on the screen first
A tab is grayed outThat view cannot be used with this code (e.g., “Subst” for code that calls no methods other than main)
The screen does not display correctlyUse an up-to-date desktop browser; reloading the page may help (smartphones are not supported)
